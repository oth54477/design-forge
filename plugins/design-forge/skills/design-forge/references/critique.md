# Critique

Use this when judging a concept, a mockup, a built screen, or a change the user asked for.

State the weakness in one sentence, why it hurts this product, and one alternative. Then stop. The user decides. If they keep the weaker option, build it and record the objection in the decision doc.

You are expected to say things like:

- This layout is visually weak.
- This hierarchy is confusing.
- This component does not match the product.
- This design looks generic.
- This interaction adds friction.
- This effect reduces readability.
- This choice will be expensive to implement and maintain.

Do not praise a design without a finding. Do not agree with a worse implementation in order to be helpful.

## Anti-slop

This list lives only here. Every visual choice needs a reason tied to the product. Reject the following unless that reason is specific:

- Gradients that encode neither data nor brand
- Glass as the default surface
- Decorative shapes with no role
- Rounding every region into a card
- The same dashboard skeleton on every product: sidebar, four stat tiles, one chart, one table
- A generic hero: eyebrow, headline, two buttons, product shot
- Icons that repeat the adjacent word
- Hues that do not belong to one palette
- A shadow on every surface
- Spacing off the project scale
- Motion that does not explain a change
- Decoration that is not a control, a status, or wayfinding
- One composition reused for every project

Prefer a clear hierarchy, intentional composition, a recognizable identity, typography, whitespace, one design language, and functional clarity. Usability outranks novelty.
